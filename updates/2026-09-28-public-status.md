# MIOIQ public status update — 2026-09-28

Deutsch: [Öffentliches Status-Update](./2026-09-28-public-status_DE.md)

> **Project rename:** AlgoSphere is becoming **MIOIQ**. It is the same continuing research and engineering project, with the same history and evidence. Historical files may still use the former name where that is necessary for provenance.

## One week later: what actually moved

The last consolidated public development update was published on **September 21, 2026**.

Since then, several long-running trust, product and infrastructure gaps have moved forward. There is still no claim that MIOIQ is Demo-ready, live-ready or that a new trading edge has been proven.

## Evidence and historical reconciliation

One previously unresolved historical OpenAI performance interpretation has now been reconciled against its original evidence population and contract.

That closes a historical trust question. It does **not** turn an older positive result into a current profitability claim.

## External AI analysis and simulated execution

The independent AI-analysis path remains active.

A concrete defect was isolated in the handoff between a valid analysis and later simulated execution handling. A source-level correction and focused regression checks are in place.

This item remains **partially open** until the currently loaded runtime and natural forward behavior prove the corrected path end-to-end.

## Login, sessions and product access

The local operator login / single-session contract has passed its reviewed scope.

This is deliberately narrower than saying that the Demo access system is finished.

**Demo registration / first-time onboarding remains open.** The connected Demo authentication/bootstrap path has not yet been proven as a complete user-facing flow.

The Settings profile presentation was also corrected so the current operator profile is no longer shown with the wrong role/profile label.

Broader account administration and multi-user productization remain open work.

## WebUI current truth

Several previously reviewed UI contracts remain useful, but the complete current WebUI acceptance is **not treated as globally closed**.

The current Cockpit/data-state path still needs a fresh end-to-end acceptance pass under the current authentication/session state, and the broader responsive/browser/device matrix remains open.

This prevents an older browser PASS from being stretched into a claim that every current screen and state is now proven.

## Storage and database work

The research database growth problem has moved forward materially.

A large logical compaction step has been completed while preserving evidence references. Future-write improvements also reduce avoidable duplication.

Physical database shrink has **not** been executed yet. That remains intentionally separated from logical compaction and requires a safe maintenance/quiescent state.

## Multi-venue direction

The execution architecture continues to move toward a venue-independent design.

Shared contracts, capability boundaries, failure handling and reconciliation behavior are being developed before broader connected execution is enabled.

This is architecture and engineering progress — not proof that multiple private exchange execution paths are already production-ready.

## Demo / Testnet

Some supporting security work has passed focused technical checks, including local credential protection and selected HTTP/WebUI safety boundaries.

But the overall Demo track remains **OPEN / NOT READY**.

Still open are the user-facing Demo registration/onboarding path, connected authentication/bootstrap proof, complete Decision → Execution → Outcome → Recovery proof, and release/distribution readiness.

A working local operator login must not be confused with a complete Demo login/onboarding product.

## Research and model quality

No new public claim of predictive superiority is being made.

Infrastructure, evidence integrity and product work have progressed, but newer research paths still require natural prospective outcomes before any claim of improved trading quality.

## Current boundary

- Research & engineering: **active**
- Paper / Shadow: **active**
- Local operator login/session: **reviewed scope passed**
- Demo registration/onboarding: **open**
- Connected Demo/Testnet E2E: **not proven**
- Full current WebUI acceptance: **open**
- Physical database shrink: **open**
- Live capital: **disabled**
- Automatic promotion: **disabled**

## Public/private boundary

MIOIQ publishes project direction, reviewed progress, methodology and selected evidence.

It does not publish the private trading application, credentials, account data, trained private models, exact strategy logic, thresholds, feature/label definitions, scoring rules, execution formulas, private prompts, internal schemas or other combinations of details that would materially reduce the work required to reconstruct the private system.

Infrastructure progress is not trading edge.

The project remains research-first and evidence-gated.
